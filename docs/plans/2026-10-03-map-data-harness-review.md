# Review of proposed national nonprofit enrichment harness

**Implementation follow-up:** The private resumable foundation is now built. See the [continuation runbook](../agent/nonprofit-enrichment-runbook.md) for current state, verified checks and remaining scope. The review below records the design decision before implementation.

2026-10-03. Scope: evaluate the supplied proposal and define the implementation boundary. No runtime implementation, data import or publication in this review.

## Decision

Implement the core approach by extending the existing acquisition system. Do not implement the proposal literally as a new schema plus 1.8 million independent agent loops. Its deterministic-first, evidence-backed, resumable design is appropriate. It is an implementation brief, not yet an evidence-backed throughput/coverage forecast.

Accept the user's no-paid-enrichment/search/geocoding/scraping/data-services constraint. Existing compute, storage and model allowances still need explicit budgets and telemetry. The deterministic pipeline must complete without model or interactive search availability; exhausted allowances produce deferred work, not paid fallback calls.

## Corrections before implementation

1. **Organization directory versus resource directory.** Preserve every in-scope identity, including foundations, associations and nonprofits without direct public services. Organization category/mission and specific offered services are separate facts. Correct the earlier assessment's requirement that every one of the first 30,000 organizations have a public resource. Target 30,000 enriched unique organization profiles, with separate verified-field and publication metrics. Current `/find` resource admission rules remain until an organization-only public projection is designed.
2. **Bulk execution before organization jobs.** Scan/join IRS and other permitted bulk sources once, then derive missing-field tasks. Partition official-site work by domain, geocoding by normalized public address, and classification by evidence hash plus taxonomy version. Use per-organization loops for unresolved reconciliation. Batch database reads/writes; do not make millions of avoidable round trips.
3. **Source order depends on the field.** After exact-EIN filing joins, validate a known official domain before attempting harder POI identity matches. Official contact/service pages can be more direct than Overture/OSM/Wikidata. Run indexed bulk POI candidate generation separately, never an all-pairs match or one remote query per organization. Filing year, return type, amended returns and source schema versions matter. A recently retrieved old filing is not current evidence of operating services.
4. **Reuse the actual schema and taxonomy.** `resource_map_organizations` already has EIN, aliases, website, phone, socials and logo fields, with a partial unique EIN index. Services, locations, evidence, curation and PostGIS also exist. `organizations` belongs to platform accounts and must not become the imported national registry. Existing taxonomy is in `src/lib/public-map/resource-categories.ts`; inspect and version it rather than waiting for a new one or creating an unrelated taxonomy. Assess relationships/multivalued assertions/job state as minimal extensions after a migration/schema comparison.
5. **Verification is not publication.** Models may propose values and evidence assessments. Deterministic code owns admission, confidence rules and writes. Current contract says “Require an identified administrator to approve the final record.” Research can be autonomous and write private evidence/staging; public auto-approval would change both policy and database promotion gates. Keep those boundaries explicit. Long-term automation for low-risk organization facts needs a separate versioned publication policy, measured error rates, audit sampling, correction/withdrawal and rollback. Do not fabricate reviewer identities or weaken service gates as an incidental harness change.
6. **Confidence must be calibrated.** A model-generated `0.98` is not a measured probability. Begin with explicit field-specific evidence rules and reason codes. Record match confidence separately from extraction accuracy, source freshness and publication eligibility. Validate numeric scores against held-out labels before using thresholds. IRS and GivingTuesday's copy of the same return are one evidence lineage, not two independent confirmations.
7. **30,000 is a rollout milestone, not the first diagnostic run.** Validate 25 records end-to-end, then 250–1,000 stratified records before a 30,000 run. Reuse the saved 10,000-record weighted benchmark for evaluation rather than restarting sampling. Maintain a representative holdout plus an explicitly separate difficult-record challenge set. Use an easy/high-yield production queue independently; report weighted results for national projections and label-based precision/recall with uncertainty. Filing-state/NTEE strata alone do not establish urban/rural coverage.
8. **Refresh needs invalidation and recovery.** Add stale/superseded assertion handling, validity dates, field dependencies, precedence and protection for owner/human corrections. Changed evidence must invalidate derived descriptions/categories where appropriate. A timeout is not proof of unavailable information. Track reason, last attempt and next eligible attempt. Store source byte hashes and versions; use transactional claims, lease tokens/fencing, unique task keys and atomic evidence/checkpoint commits so an expired worker cannot overwrite newer results.
9. **The agent boundary needs concrete limits.** Treat fetched text as untrusted data; isolate browser research from personal/authenticated sessions and production credentials. Reuse existing SSRF/redirect/DNS checks, robots, global host pacing and byte/request/time limits. Add parser limits for XML external entities and archive expansion. No arbitrary SQL or publication tool in the research model's toolset. `--all` means a resumable sequence of bounded jobs, not unlimited network/model use or implicit publish authorization.
10. **Avoid storing bulk research in hot production tables.** Keep source snapshots and bounded evidence artifacts private on existing storage; use a transactional research ledger and batch normalized exports. Store canonical public projections in Postgres only through the appropriate controlled path. Add Python/DuckDB selectively for a measured bulk-data need; retain existing Node command orchestration. Do not introduce Python, Polars and DuckDB together simply because the proposal lists them.

## Source checks and practical limits

- [GivingTuesday data marts](https://990data.givingtuesday.org/datamarts/) provide reusable 990/990PF/990EZ extracts and direct users to Basic Fields. This is a strong candidate for avoiding custom parsing, but its [data license is ODbL](https://990data.givingtuesday.org/data-use-license/). Evaluate the exact artifact and redistribution obligations; compare with direct IRS XML before selecting the canonical source. This review did not download or measure field coverage in its extracts.
- [Overture Places](https://docs.overturemaps.org/guides/places/) can contribute domain/phone/social/location candidates; its confidence score measures place existence, not an EIN match or every field's accuracy. Its current guide explicitly lists duplicate/property-completeness issues. Preserve upstream IDs and lineage; do not assume it identifies legal nonprofit entities. Use [release/source-specific licensing](https://docs.overturemaps.org/attribution/), not one blanket license for all Overture themes.
- OSM bulk data is distinct from the public Nominatim endpoint. The [public service policy](https://operations.osmfoundation.org/policies/nominatim/) discourages bulk geocoding, caps general use at one request/second and further restricts long-running jobs. Do not use it as the national batch engine. Prefer permitted bulk extracts and supported batch alternatives.
- [Census geocoding](https://www.census.gov/programs-surveys/geography/technical-documentation/complete-technical-documentation/census-geocoder.html) supports up to 10,000 addresses per batch, but coordinates are interpolated from address ranges. Record precision/match quality; do not call every point a verified entrance/rooftop or use a geocode to establish service-location status.
- Website logos/favicons are candidates. Separate trademark status, copyright/license and approved display policy rather than treating them as mutually exclusive rights states. Defer asset downloading/public display until identity/contact/location processing works. A favicon is not automatically a suitable organization logo.
- “Web search through Codex” is an optional operator/agent capability, not a demonstrated unattended CLI dependency. Validate the actual runtime interface, restart behavior and allowances before enabling it. Offline/bulk processing must work when that adapter is absent.

## First implementation slice

Use `feat/map-data-scale-20261003` and preserve the root/private research state.

1. Port the scoped existing acquisition modules, commands and focused tests onto the current-main base; reuse the acquisition skill and contracts rather than creating conflicting AGENTS files.
2. Build one versioned IRS/filing bulk adapter that yields EIN-linked website/phone/mission/address candidates. Compare direct XML with available permitted preprocessed extracts before selecting implementation dependencies. Preserve source date, content hash and schema version.
3. Add durable bounded queue state and domain cache behind existing interfaces; fix whole-file JSONL rewrite bottlenecks. Emit field evidence and deterministic verification decisions to a private staging export.
4. Run replay/crash-resume, conflict, stale-evidence and entity-match tests; dry-run the existing benchmark. Prepare a 25-record live sample with exact input IDs, domains and request/byte/time ceilings, then evaluate a 250–1,000-record cohort.
5. Report exact field gains and failures, host/cache savings, model calls and retained bytes. Produce a database write diff and rollback plan before applying any live schema/data changes. Build the 30,000 runner after the first measured iteration.

CLI should distinguish planning, bounded execution/resume, status/reporting, export and controlled apply. Sampling must be seeded and snapshot-bound. Existing public promotion remains separate from enrichment. A source- or field-level circuit breaker must stop systematic mismatches before a batch enters canonical storage.

Search delivery remains a parallel implementation requirement: current browser index traversal cannot be the national lookup strategy. Use bounded server-side search/viewport filtering, cached counts and clustering over existing Postgres/PostGIS; preserve detail-on-demand.
