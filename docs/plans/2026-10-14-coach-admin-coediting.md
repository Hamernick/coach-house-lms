## Findings from current source

- React Grab's route points to the host page; the matching dialog belongs to `src/features/member-workspace/components/projects/organization-core-document-editor.tsx`. It initializes content/budget rows from a snapshot, saves manually, submits `expectedLastUpdated`, displays returned error text and closes on success. It has no live document subscription or merge interface and does not consume the action's `currentSection` conflict response.
- `src/actions/roadmap.ts` rejects a changed section revision and also compares the organization row's `updated_at` when writing the entire profile JSON. A concurrent write to another profile field during that read/write window can also reject the save. This protects against silent overwrite but does not resolve concurrent edits. It is a plausible explanation, not a confirmed incident diagnosis. Storage entitlement/access errors are additional distinct paths to reproduce.
- Text editor undo/redo buttons already exist. Installed Tiptap3.17.1 UndoRedo defaults to100 grouped history events with500ms grouping; the application does not override it. This is editor-session history, not100 durable document versions. Closing/reopening creates a new editor. Budget row undo is not established by rich-text undo.
- Roadmap narrative “revisions” are last-updated tokens. The document activity trigger records actor/title/document key, not old document bodies. No durable core-document content restore interface/storage was found in this inspected path. Do not confuse fiscal revisions, file trash restore, activity events or backups with this feature.
- `member-workspace-org-switcher.tsx` uses membership-derived options and reloads the page after selection. Both `load-accessible-organizations.ts` and `active-org.ts` resolve owner/membership access. Adding every organization to the menu alone would not authorize downstream reads/writes.
- `resolveOrganizationDocumentAccess` already supports explicit organization targets for authenticated platform staff with organization capability and coach-scope authorization, preserving actor ID on elevated server writes. It still checks document-storage entitlement. Staff privileges and organization membership are different concepts.
- Workspace cursor overlay exists, but the reported dialog does not mount it. The generic cursor hook generates session IDs and broadcasts the supplied name; it is not proof of authenticated staff identity or document authorization. Presence needs server-authorized organization/document rooms and verified identity/role, including visible viewers who are not moving their mouse.

## Recommended approach

Use a single shared document-editing implementation for members and staff. Keep a distinct authenticated staff support context rather than impersonating the owner or creating blanket organization memberships. Admin organization switching is a useful access/navigation improvement, not a substitute for safe saving and collaboration.

1. Reproduce owner/coach editing with two sessions. Preserve drafts and expose Saving/Saved/Offline/Conflict accurately. Fix stale revision handling without removing concurrency guards. Separate organization-wide profile updates from section-scoped atomic writes; preserve unrelated changes. On conflicting same-field edits, preserve both drafts until a collaboration-aware merge or explicit resolution succeeds. Save acknowledgement must mean durable server acceptance.
2. Add durable, actor-attributed snapshots and restoration before broad concurrent editing. Proposed bounded policy: latest100 meaningful versions plus daily checkpoints for30days; confirm storage budget/retention before schema finalization. Avoid per-keystroke snapshot growth. Include text, budget rows and necessary asset references. Preview before restore; restoration creates a new version and is itself reversible. Protect attachments needed by retained versions. Local undo should undo the actor's edits without erasing another person's contributions.
3. Implement actual simultaneous rich-text collaboration plus live saved updates on all relevant member/admin/profile views. Use the existing Tiptap-compatible collaboration approach after choosing and validating transport/persistence. Do not replace an actively edited buffer with remote HTML. Persist collaboration state, reconnect safely, avoid duplicate initial seeding, include budget rows and all alternate writers, and maintain compatible schema/projections. A temporary lock/manual conflict fix alone does not meet the requested simultaneous-editing acceptance.
4. Extend the existing switcher through a dedicated platform support capability for the explicitly designated staff identities, resolved to exact active Auth IDs; no client email allowlist or implicit developer-role promotion. Recheck every server action, RLS/storage access and realtime subscription; preserve actor identity and display an obvious organization/support context. All users see staff name/role, viewing/editing state and live cursor/selection where applicable, with leave/revoke/disconnect cleanup. A hidden tab or presentation mode must not falsely imply nobody is viewing.

Official reference checked October14: [Tiptap collaboration](https://tiptap.dev/docs/editor/extensions/functionality/collaboration) provides collaboration-specific history and requires disabling StarterKit's ordinary UndoRedo when used. This plan selects neither a paid service nor a production provider change.
